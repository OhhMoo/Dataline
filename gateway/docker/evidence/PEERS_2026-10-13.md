## Why the question exists

native-services binds every agent listener on `0.0.0.0` (`compose.native.yml`, `--bind 0.0.0.0`). It
sits on `episode_net` only, except when a profile plugs a hosted engine (`HOSTED_ENGINES`: today only
BigQuery). Then `profile_overlay` also puts it on `backend_net`, so that it can reach the emulator.

From that moment every agent listener (jira:8080, ..., bigquery:9050, the aggregate 8099) also answers
on native-services' `backend_net` address. The peers there are postgres, minio and the BigQuery engine
(and snowflake, under a `warehouse=bigquery,snowflake` plug override).

| `de/gcp` run 2 | `backend_net` 10.210.1.0/24 | `episode_net` 10.210.2.0/24 |
|---|---|---|
| native-services | 10.210.1.5 | 10.210.2.4 |
| minio | 10.210.1.3 | 10.210.2.2 |
| postgres | 10.210.1.4 | 10.210.2.3 |
| bigquery (engine) | 10.210.1.2 | (not attached) |
| episode | (not attached) | 10.210.2.5 |

## Method

- **The witness.** A listener in native-services' own container, bound like the agent listeners
  (`0.0.0.0:18099`). It logs each connection's peer and local address, and the first bytes received.
- **Network.** A sidecar in each peer's network namespace (`docker run --network container:<peer>`)
  resolves names and dials the witness at native-services' `backend_net` address. This is an
  instrument: it shows the path exists, not that the agent can use it.
- **Agent-driven.** Every attempt below was issued from the **episode container**, with what the box
  carries, except the MinIO `mc` row (see that row).

## Findings

**The path exists from every backend_net peer.** From postgres, minio and the engine, the compose name
`native-services` resolves to its `backend_net` address (10.210.1.5), and a TCP dial there connects.
The witness saw each one arrive from the peer's `backend_net` address.

`jira.internal` resolves only from the dual-homed peers, and there it names the `episode_net` address
(10.210.2.4). The engine resolves neither alias.

## What this means for Task 6

- **A backend_net peer can be driven** (MinIO, with the root credential every box carries), so step 1's
  gate is passed and the filter is wanted.
  - A connection MinIO opens to native-services' `backend_net` address is counted as the episode's own
    destination: jira went 0 to 4.
  - The listener filter (agent listeners admit only `ALKERA_EPISODE_SUBNETS`) refuses exactly that path:
    the raw `backend_net` address and the compose name `native-services`.
- **What the filter cannot close.** MinIO and Postgres are also on `episode_net`, so the same job named
  `jira.internal:<port>` arrives from MinIO's `episode_net` address, inside the episode subnet. A subnet
  filter cannot tell that dial from the agent's own.
  - The cause is the credential: the box's S3 identity is MinIO's root user, which owns the admin API
    (batch jobs, notify targets, restarts).
  - Closing it means a non-admin S3 identity for the box, or MinIO off `episode_net` behind an audited
    proxy. That is outside T6's files, and is noted for the coordinator.
- **Side finding (not T6's).** A `gs://` external table over REST is not fenced by the BigQuery proxy.
  It reaches the engine and hangs past a 30 s client timeout, where it should be refused by name like
  load jobs.

## Reproduce

The drivers are `peers_probe.py` (before) and `peers_after.py` (after). They are kept outside the
repository, as the instruments of this note, at `~/.cache/alkera-harbor-work/t5-peers-evidence/`
together with the raw JSON of all three runs. They run through the slot:

```
TMPDIR=~/.cache/alkera-harbor-work/tmp scripts/docker_slot.sh --lock bigquery_e2e \
  "gateway/.venv/bin/python peers_probe.py --image alkera-episode:t5-bigquery --out peers-de-gcp.json"
```

It does the following, in order:
1. Builds the `de/gcp` world and runs `TourTopology.up()`.
2. Starts the witness (`docker exec -d native-services python -c <listener on 0.0.0.0:18099>`).
3. Dials the witness from the episode as a control (`jira.internal:18099`, arriving from 10.210.2.5).
4. Runs the netns sidecars.
5. Runs the agent-driven attempts above, each followed by a read of the witness log and of
   `destinations.jsonl`.
6. Calls `stack.down()`.

## Addendum: the MinIO door closed (d02a988, measured at 644dc07)

The cause above was the credential: the box's S3 identity was MinIO's root. Since `fix(minio): the
box's S3 identity is a scoped user, not MinIO's root`, MinIO's own entrypoint
(`gateway/docker/minio_start.sh`) mints a random root on every start, which exists only in that
process, and provisions the box's unchanged `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` as an
ordinary user holding `minio_box_policy.json`: the world bucket's S3 data actions, plus an explicit
Deny on `admin:*` and `kms:*`. No golden, discovery file or world digest moved.
